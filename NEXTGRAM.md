# Кастомизация поверх Telegram-Android

Патч поверх `DrKLO/Telegram` 13.1.1 (7237), коммит `3de37c8`.

## Что работает

- **Режим кастомизации.** Включается в «Настройки → Оформление → Режим кастомизации». Внизу появляется панель с кнопкой «Готово». Обычные касания работают как всегда: по экранам можно ходить и листать. Если зажать элемент на 0,32 с, режим выберет его и откроет панель свойств. Это быстрее системного долгого нажатия, поэтому меню сообщения не откроется.
- **Каскад уровней.** Глобально → категория чата (контакты / не контакты / группы / каналы / боты, как в папках Telegram) → папки → конкретный чат. Слияние идёт по свойствам: если в чате задан только цвет времени, остальное наследуется с общих уровней. Под каждым свойством видно, с какого уровня пришло значение.
- **Заготовка для сообщения** (входящие и исходящие — отдельные элементы):
  - время: секунды, свой цвет, скрытие;
  - кнопка «Скрыть части касанием»: панель закрывается, и тап по части скрывает её или возвращает. В режиме редактирования скрытая часть видна блёкло и под спойлером, после выхода из режима исчезает совсем.
- **Авторежим для всего остального.** Это цвета темы, найденные через `ThemeDescription` текущего экрана. Цвет ключа меняется везде, где этот ключ используется, и сохраняется отдельно для каждой темы и акцента. Файл темы не меняется.
- **Свой api_id и пуши через свой Firebase** (см. ниже).

Конфиг лежит в `files/nextengine.json` внутри данных приложения. Формат описан в `ConfigCodec`. Если файл не читается, он переименовывается в `nextengine.json.broken`, а приложение стартует с пустым конфигом.

## Где что лежит

```
TMessagesProj/src/main/java/org/nextgram/engine/
  core/            чистая Java без Android: модель, уровни, каскад, JSON (покрыто тестами)
  NextEngine.java   загрузка/сохранение, кэш каскада, слушатели
  ScopeResolver    категория и папки чата
  EngineColors     переопределение ключей темы (хук в Theme.getColor)
  EngineStrings    строки ru/en (в strings.xml не лезем — меньше конфликтов)
  hooks/           хуки для апстримных классов
  edit/            режим редактирования: оверлей, хит-тест, заготовки, панель, пикер цвета
nextengine-tests/   тесты ядра на обычной JVM
```

## Правки в апстримных файлах

Каждая правка — одна-две строки с пометкой `// custom` и полными именами классов, чтобы не трогать импорты:

| Файл | Что |
|---|---|
| `ui/Cells/ChatMessageCell.java` | форматтер времени (2 места), скрытие времени, цвет времени, метод `getCustomTimeBounds` в конце класса |
| `ui/ActionBar/Theme.java` | одна строка в `getColor` |
| `ui/ActionBar/ThemeDescription.java` | два геттера |
| `ui/LaunchActivity.java` | `dispatchTouchEvent` |
| `ui/ThemeActivity.java` | пункт «Режим кастомизации» |
| `messenger/BuildVars.java`, `TMessagesProj/build.gradle` | api_id из `local.properties` |

При мердже новой версии Telegram конфликты будут только в этих строках: `git grep -n "custom"`.

## Как добавить заготовку

1. Класс `EditorSpec` в `custom/edit/`: id элемента, части с границами и свойства. Пример — `MessageCellSpec`.
2. Строка в `SpecRegistry`.
3. Хуки в апстримном классе: на каждое свойство одна строка, которая вызывает метод из `custom/hooks/`. Значения берите через `NextEngine.resolve(account, dialogId, elementId)`: кэш делает этот вызов дешёвым даже в `onDraw`.
4. Если части нужно скрывать, отдайте их границы в `partBounds`, а в хуке не рисуйте часть и уберите её из раскладки. Спойлер в режиме редактирования оверлей нарисует сам.

## Пуши — как рекомендует Telegram

Код приёма FCM в Telegram уже есть: `PushListenerController`, payload шифруется по MTProto (`secret` в `account.registerDevice`). Менять нужно только конфигурацию:

1. Получите api_id и api_hash на <https://my.telegram.org/apps> и пропишите их в `local.properties` в корне:
   ```
   TELEGRAM_APP_ID=1234567
   TELEGRAM_APP_HASH=0123456789abcdef0123456789abcdef
   ```
   Без них сборка возьмёт тестовый ключ из исходников Telegram. По документации он ограничен на сервере и для релиза не годится.
2. Задайте свой package в `gradle.properties`: `APP_PACKAGE=com.example.yourclient`. Тогда клиент встанет рядом с официальным Telegram.
3. Создайте проект в Firebase, добавьте в него Android-приложение с этим package и положите его `google-services.json` вместо телеграмовских в `TMessagesProj/` и `TMessagesProj_App/`.
4. На <https://my.telegram.org/apps> укажите для своего api_id FCM-учётные данные этого Firebase-проекта. Ключ сервисного аккаунта в APK не кладите.

Подробнее: <https://core.telegram.org/api/push-updates>.

## Перед публикацией (ToS Telegram API)

- В названии не должно быть слова «Telegram», кроме формы «Unofficial Telegram».
- Не используйте официальный логотип: замените иконки в `res/mipmap-*`.
- Нужен свой api_id (пункт 1 выше).
- Исходники нужно публиковать: код под GPL.

## Ограничения этой версии

- Хит-тест по частям есть только у сообщения, и часть у него одна — время. В каналах время скрывается вместе с подписью автора: Telegram рисует их одной строкой.
- В авторежиме доступны только цвета темы: большинство ячеек Telegram рисуют всё на канвасе, и без заготовки внутрь не залезть.
- В чатах с собственной темой чата (обои/тема конкретного чата) её цвета перекрывают изменённые цвета темы.
- Для элементов, которых нет на экране, сэмплов пока нет: редактируются только реальные данные.
- Размер текста по уровням не сделан: Telegram меряет текст сообщений общим статическим Paint, и для этого нужна отдельная заготовка.
